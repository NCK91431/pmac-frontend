# EMS电力负荷历史数据接口文档

## 文档概述

本文档描述了电力负荷管理系统的历史数据查询接口，包括用户鉴权和负荷数据获取两个核心接口。文档适用于需要获取各公司逐时负荷数据的场景。

**接口提供方：** EMS电力负荷管理系统
**数据类型：** 电力负荷历史数据
**更新频率：** 实时

***

## 接口基础信息

### 通用说明

- **请求协议：** HTTPS
- **字符编码：** UTF-8
- **数据格式：** JSON
- **时间格式：** ISO 8601（如：2025-10-01T00:00:00Z）
- **日期格式：** YYYY-MM-DD（如：2025-10-01）

***

## 接口1：用户鉴权登录

### 接口描述

获取系统访问令牌（accessToken），用于后续接口的身份验证。

### 请求信息

**接口地址：**

```
https://ems.pmac.com.cn/api/pbp-system/v1/user/login
```

**请求方式：**

```
POST
```

**请求头（Headers）：**

```
Content-Type: application/json
```

**请求参数（Body）：**

| 参数名      | 类型     | 必填 | 说明      | 示例值                                                              |
| -------- | ------ | -- | ------- | ---------------------------------------------------------------- |
| userName | String | 是  | 用户名     | vpp                                                              |
| password | String | 是  | 密码（已加密） | 1701f6e61930d52216bb3fe93e414bd0956583ddc37dc1c69db7abff79243bd2 |
| r        | String | 否  | 随机参数    | 3825                                                             |

**请求示例：**

```json
{
  "userName": "vpp",
  "password": "1701f6e61930d52216bb3fe93e414bd0956583ddc37dc1c69db7abff79243bd2",
  "r": "3825"
}
```

### 响应信息

**响应参数：**

| 参数名                  | 类型      | 说明            |
| -------------------- | ------- | ------------- |
| status               | Integer | 状态码，0表示成功     |
| data                 | Array   | 返回数据数组        |
| data\[0].accessToken | String  | 访问令牌，后续接口需要使用 |
| message              | String  | 响应消息          |

**成功响应示例：**

```json
{
  "status": 0,
  "data": [
    {
      "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "expireIn": 7200
    }
  ],
  "message": "success"
}
```

**失败响应示例：**

```json
{
  "status": 1001,
  "data": null,
  "message": "用户名或密码错误"
}
```

## 接口2：获取历史负荷数据

### 接口描述

根据公司ID和日期范围，获取指定公司的历史逐时负荷数据。

### 请求信息

**接口地址：**

```
https://ems.pmac.com.cn/api/vpp-manage/v1/ps/load/predicting/unit/load/data
```

**请求方式：**

```
GET
```

**请求头（Headers）：**

| 参数名           | 类型     | 必填 | 说明                     | 示例值                                            |
| ------------- | ------ | -- | ---------------------- | ---------------------------------------------- |
| Authorization | String | 是  | 认证令牌，格式：Bearer {token} | Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... |
| Content-Type  | String | 是  | 内容类型                   | application/json                               |

**请求参数（Query Params）：**

| 参数名        | 类型     | 必填 | 说明      | 示例值                 |
| ---------- | ------ | -- | ------- | ------------------- |
| customerId | String | 是  | 公司/客户ID | 1993139538440470529 |
| startDate  | String | 是  | 开始日期    | 2025-10-01          |
| endDate    | String | 是  | 结束日期    | 2025-11-01          |

**请求示例：**

```
GET https://ems.pmac.com.cn/api/vpp-manage/v1/ps/load/predicting/unit/load/data?customerId=1993139538440470529&startDate=2025-10-01&endDate=2025-11-01

Headers:
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Content-Type: application/json
```

### 响应信息

**响应参数：**

| 参数名                | 类型      | 说明                |
| ------------------ | ------- | ----------------- |
| status             | Integer | 状态码，0表示成功         |
| data               | Array   | 负荷数据数组            |
| data\[].dataTime   | String  | 数据时间点（ISO 8601格式） |
| data\[].actualLoad | Decimal | 实际负荷值             |
| data\[].unitPkId   | String  | 单位ID              |
| data\[].unitName   | String  | 单位名称              |
| message            | String  | 响应消息              |

**成功响应示例：**

```json
{
  "status": 0,
  "data": [
    {
      "dataTime": "2025-10-01T00:00:00Z",
      "actualLoad": 1250.5,
      "unitPkId": "1993139538440470529",
      "unitName": "台山市人民医院"
    },
    {
      "dataTime": "2025-10-01T01:00:00Z",
      "actualLoad": 1180.3,
      "unitPkId": "1993139538440470529",
      "unitName": "台山市人民医院"
    }
  ],
  "message": "success"
}
```

**失败响应示例：**

```json
{
  "status": 1002,
  "data": null,
  "message": "用户ID不存在"
}
```

## 数据处理规范

### 时间映射规则

原始接口返回的小时数据需要按照以下规则进行转换：

| 原始小时 | 转换后列名 | 说明        |
| ---- | ----- | --------- |
| 0    | 1时    | 对应当天00:00 |
| 1    | 2时    | 对应当天01:00 |
| 2    | 3时    | 对应当天02:00 |
| ...  | ...   | ...       |
| 22   | 23时   | 对应当天22:00 |
| 23   | 24时   | 对应当天23:00 |

### 数据透视格式

**要求输出格式：**

| 日期         | 1时     | 2时     | 3时     | ... | 23时    | 24时    |
| ---------- | ------ | ------ | ------ | --- | ------ | ------ |
| 2025-10-01 | 1250.5 | 1180.3 | 1105.8 | ... | 1320.6 | 1285.2 |
| 2025-10-02 | 1275.3 | 1205.6 | 1132.1 | ... | 1345.8 | 1310.4 |

**转换逻辑：**

1. 从原始数据中提取日期（YYYY-MM-DD）和小时（0-23）
2. 将小时+1得到列名（1时、2时...24时）
3. 以日期为行，以转换后的小时列为列，进行数据透视
4. 填充对应的负荷值到对应单元格
5. 缺失的小时数据填空值（null或空字符串）

## 数据范围计算规则

### 日期范围定义

- **当前日期：** 记为 D（如：2026-03-19）
- **结束日期：** D - 4天（即 D-4）
- **开始日期：** D - 35天（即 D-35）
- **数据天数：** 32天（包含开始日期和结束日期）

### 计算示例

**假设当前日期 D = 2026-03-19**

```
结束日期 = 2026-03-19 - 4天 = 2026-03-15
开始日期 = 2026-03-19 - 35天 = 2026-02-12
数据范围 = 2026-02-12 至 2026-03-15（共32天）
```

**接口请求参数：**

```
startDate: 2026-02-12
endDate: 2026-03-15
```

## 错误码说明

### 通用错误码

| 错误码  | 说明       | 处理建议                  |
| ---- | -------- | --------------------- |
| 0    | 成功       | -                     |
| 1001 | 用户名或密码错误 | 检查鉴权参数                |
| 1002 | 用户ID不存在  | 检查customerId参数        |
| 1003 | 日期格式错误   | 确保日期格式为YYYY-MM-DD     |
| 1004 | 日期范围无效   | 确保startDate ≤ endDate |
| 5000 | 系统内部错误   | 稍后重试                  |

### HTTP状态码

| 状态码 | 说明    | 处理建议        |
| --- | ----- | ----------- |
| 200 | 请求成功  | -           |
| 401 | 未授权   | 检查token是否有效 |
| 403 | 禁止访问  | 检查权限配置      |
| 404 | 接口不存在 | 检查接口地址      |
| 500 | 服务器错误 | 稍后重试        |
| 503 | 服务不可用 | 稍后重试        |

## 开发注意事项

### 调用建议

1. **超时设置：** 建议设置请求超时时间为30-60秒
2. **重试机制：** 接口调用失败时，建议实现指数退避重试机制
3. **并发控制：** 获取多个公司数据时，建议控制并发数量（建议不超过5个并发）
4. **数据验证：** 接收数据后应验证数据完整性，确保每小时都有数据

### 数据质量检查

- 检查返回数据是否为空
- 检查日期是否连续
- 检查负荷值是否在合理范围内（如：非负数、非异常大值）
- 检查时间戳格式是否正确

### 性能优化

- 使用连接池管理HTTP连接
- 批量获取数据时使用异步请求
- 合理缓存已获取的数据，避免重复请求
